# CLAUDE.md — imiron-brand

> Рабочие соглашения репозитория для людей и AI-ассистентов (Claude Code).

## Назначение

Единый источник истины для личного бренда Александра Мирошниченко (iMironRU).
Контент о владельце пишется один раз, хранится структурированно и собирается
в представления под каждую площадку. Устраняет рассинхрон витрин (профиль GitHub,
GitHub Pages / imiron.ru, резюме, Хабр, Инфостарт, соцсети).

## Главный принцип

**Один источник → много представлений.**

- Факты — только в `data/*.json`. Нигде не дублировать руками.
- Нарративы — только в `content/`.
- Витрины генерируются сборщиками из `build/`. Готовые артефакты в `dist/`
  и в репозиториях витрин руками **не правятся** — правка идёт в источник, затем пересборка.

## Маркеры площадок (targets)

Аналог маркеров применимости (vuz/spo/do) из edu-framework, но для витрин.
Каждый элемент данных и блок контента может нести поле `targets`:

- `["all"]` — во все витрины;
- отсутствие поля — трактуется как «везде»;
- `[]` — никуда (например, устаревший контакт);
- список маркеров — только в указанные.

Допустимые маркеры: `github-profile`, `github-pages`, `site`, `app`, `book`,
`resume`, `habr`, `infostart`.

## Идентичность: четыре регистра одного образа

`data/identity.json` хранит один образ в нескольких регистрах, а `titleByTarget`
раскладывает их по витринам:

- **epigraph** (везде): «Доктором я не стал — зато научился учить».
- **formal** (resume, habr, infostart, github-profile): «Архитектор информационных
  систем на 1С, бизнес-аналитик, преподаватель».
- **portrait** (site, github-pages): «Архитектор для нерешаемого. Ментор для тех,
  кто хочет так же».
- **voice** (telegram, подписи): «Ай-ти-поп. Но проповеди у меня практические».

Голос автора (ирония без инфоцыганщины, самоирония вместо хвастовства) — часть
бренда. При редактуре не выхолащивать.

## Резюме

`data/resume.json` — по стандарту JSON Resume (jsonresume.org). Рендерится темами
JSON Resume в HTML/PDF/Markdown. Поля `_meta`, `_todo`, `note` нестандартные —
рендереры их игнорируют. Незакрытые пункты — в массиве `_todo`.

## Соглашения по данным

- Валидный JSON, проходящий схему из `schema/`. Перед коммитом — `npm run validate`.
- UTF-8, отступ 2 пробела.
- `id` — латиница, kebab-case, уникальны в файле.
- Даты — ISO 8601 (`YYYY` или `YYYY-MM`).
- Никаких секретов: токенов, паролей, ключей. Домашний адрес и личный телефон
  на публичные витрины не выносить.

## Рабочий процесс

**Добавить проект/книгу/приложение/кейс:** дописать запись в `data/`, проставить
`targets`, `npm run validate`, пересобрать витрины.

**Изменить факт о себе:** правка только в `data/`, затем пересборка. Готовые
артефакты не трогать.

```bash
npm run validate
npm run build           # профиль + резюме
npm run build:profile
npm run build:resume
```

## Принципы для AI-ассистента

- Предлагать изменения файловой системы командами, а не выполнять молча.
- Не дублировать факты: если факт есть в `data/`, переиспользовать.
- Менять источник и шаблон, а не сгенерированный артефакт.
- Сохранять авторский голос в нарративах.
